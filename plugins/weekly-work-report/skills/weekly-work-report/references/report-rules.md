# 주간업무보고 작성 규칙

## 자료 수집

- 기본 원본은 OneNote `동원정밀` 전자필기장 > `Dashboard` 섹션 > `Dashboard` 페이지다.
- 표 번호가 아니라 표 제목으로 찾는다.
  - `Completed : 이주완료`: 금주 진행사항
  - `Doing : 담당자별로 현재 업무 표시`: 차주 예정사항
- 보고서에 사용하는 모든 Task 링크 페이지에서 다음을 읽는다.
  - `주요 결과물`
  - 시작일과 종료일
  - 전체 `이력` 목록
- 보고 기간에 포함되는 이력을 우선 반영한다. 확인되지 않은 사실은 보완하거나 추정하지 않는다.
- 링크 페이지를 읽지 못하면 Dashboard 행의 확인 가능한 내용만 사용하고 최종 응답에 누락 페이지를 표시한다.
- Dashboard 링크의 `page-id`가 `onenote_read_page`에서 HRESULT `0x80042005`를 반환하면 정확한 링크 제목으로 검색하고, 검색 결과의 로컬 페이지 ID로 다시 읽는다.
- 같은 제목이 여러 개면 예상 전자필기장과 섹션에 속한 결과를 우선하고, 그다음 최근 수정 시각을 사용한다. 그래도 모호하면 후보 내용을 읽고 선택 근거를 기록한다.
- 일반 수집은 `includeXml: false`로 수행한다. 원문 링크나 구조를 텍스트에서 확인할 수 없을 때만 XML을 읽는다.
- OneNote 읽기 연결이 없으면 작업을 중단하고 연결 또는 최신 자료를 요청한다. 이전 실행에서 남은 자료를 대신 쓰지 않는다.
- PC 화면 자동화와 Excel/OneNote UI 조작은 금지한다.

## 날짜와 주차

- 사용자가 기준일을 지정하면 그 날짜를 사용한다.
- 지정이 없으면 요청일이 목요일인 경우 당일, 그 외에는 직전 목요일을 기준일로 한다.
- 월 주차는 기준일이 속한 달의 몇 번째 목요일인지로 계산한다: `((기준일의 일 - 1) // 7) + 1`.
- `X3`에 기준일을 기록한다. `H4`와 `T4`의 기존 수식은 수정하지 않는다.
- 금주 및 차주 기간 표시는 템플릿의 기존 수식과 캐시 값을 유지·갱신한다. 현재 템플릿의 의미는 금주 `기준일-6일 ~ 기준일`, 차주 `기준일+1일 ~ 기준일+8일`이다.

## 템플릿과 출력

- 템플릿 우선순위는 다음과 같다.
  1. 사용자가 지정한 정상 `.xlsx`
  2. 작업 폴더와 이전 출력 폴더를 합쳐 보고 기준일이 가장 최근인 정상 주간업무보고 `.xlsx`
  3. 보고 기준일이 같으면 최근 수정 파일을 우선한다.
- Excel 복구 로그가 발생했거나 검증에 실패한 파일은 템플릿으로 사용하지 않는다.
- 후보 템플릿은 출력과 동일한 파일을 지정해 검증기를 실행하여 ZIP 무결성, 네임스페이스, 수식, 인쇄영역과 프린터 설정을 먼저 확인한다.
- 파일명은 `YYYY년 M월 N주차 주간업무현황 - 소프트웨어.xlsx`다.
- 출력 디렉터리는 `D:\doc\주간업무보고\outputs\YYYY-MM-DD\`다.
- 해당 디렉터리에는 최종 보고서 한 파일만 둔다. 다른 파일을 지울 필요가 있으면 삭제 전 정확한 경로를 확인한다.
- 템플릿을 ZIP 패키지 수준에서 복사한다. 높이, 테두리, 병합, 수식, 스타일, 인쇄영역, 반복 행과 프린터 설정은 변경하지 않는다.
- 금주 `C:O`와 차주 `P:Z`의 합계 폭은 같아야 한다. 합계가 다르면 `C:Z`의 전체 폭을 유지한 채 두 영역의 합계 폭만 균등하게 조정한다.

## 셀 배치와 내용

- 워크시트 이름: `주간업무보고`
- 보고서 범위: `B2:Z39`
- 인쇄영역: `$B$2:$Z$39`
- 반복 행: `$2:$6`
- 기준일: `X3`
- 금주 진행사항: `C8:C32`
- 차주 예정사항: `P8:P32`
- 각 영역은 최대 20행만 사용한다. 빈 문자열은 의도적인 구분 행으로 취급한다.
- 계층 표시는 프로젝트 `▶`, 첫 번째 업무 단계 `▷`, 상세 결과 `-`를 사용한다. 프로젝트 사이에는 빈 행 하나를 둔다.
- Task별 제목과 핵심 결과를 짧게 정리한다. 한 셀에 긴 문장을 넣어 본문이 잘리지 않게 한다.
- `Completed`와 `Doing` 표의 소속이 금주와 차주 분류를 결정한다.
- `Completed`에서 보고 기간에 완료 또는 수행된 내용을 금주에 넣는다. 기간 내 이력이 없으면 Task 제목과 `주요 결과물`만 사용하고 이전 기간 이력을 금주 실적으로 표현하지 않는다.
- `Doing`에서 현재 진행 중이거나 다음 기간에 이어질 확인 가능한 내용을 차주에 넣는다.
- 시작일, 종료일과 이력 날짜가 다르면 실제 이력은 유지하되 날짜 불일치를 추정으로 보정하지 않는다.
- 같은 사실을 Dashboard와 이력에서 중복 작성하지 않는다.
- 한 페이지 렌더에서 잘리면 문장을 축약하거나 행 수를 줄인다. 서식이나 인쇄 배율을 변경해 맞추지 않는다.

## 검증과 최종 응답

- `validate_weekly_report.py`가 성공해야 한다.
- 검증기는 입력 JSON의 비어 있지 않은 각 행이 `C8:C32`와 `P8:P32`의 정확한 주소와 값에 존재하는지 확인해야 한다.
- 중복 행, 중복 셀 주소와 상위 행 번호가 다른 셀 주소가 없어야 한다.
- `sheet1.xml`의 `mc:Ignorable` 토큰에 대응하는 네임스페이스 선언이 모두 있어야 한다.
- `calcChain.xml`과 `printerSettings1.bin`은 원본과 바이트 단위로 같아야 한다.
- 허용된 `sheet1.xml`과 `sharedStrings.xml` 외의 XLSX 멤버는 원본과 바이트 단위로 같아야 한다.
- 인쇄영역 `$B$2:$Z$39`와 반복 행 `$2:$6`을 확인한다.
- 금주 `C:O`와 차주 `P:Z`의 합계 폭 차이는 `0.001` 이하여야 하며 `C:Z`의 전체 폭은 템플릿과 같아야 한다.
- Artifact Tool로 `B2:Z39`를 다시 불러와 검사·렌더링하고 날짜, 분류, 잘림, 한 페이지 배치를 눈으로 확인한다. 렌더러가 원본에도 있는 `TEXT(...)` 수식만 `#VALUE!`로 표시하면 수식을 바꾸지 말고, XML 캐시 값과 수식 보존 검증 결과를 사용해 날짜를 확인한 뒤 렌더러 한계를 최종 응답에 밝힌다.
- 최종 응답에 다음 참조자료를 모두 표시한다.
  - 사용한 Dashboard 표 이름
  - 사용한 각 Task 링크 페이지 제목
  - 읽지 못한 링크 페이지와 사용하지 못한 항목
  - 템플릿 파일의 전체 경로
